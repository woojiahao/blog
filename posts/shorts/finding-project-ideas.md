> Posted elsewhere, but sharing here

1. **Curiosity about daily tools** 

    Usually you can start with some curiosity about the tools you interact with daily, like “How does Figma work?” or “How does Google Docs collaborative workflow work?” and you can often find resources online that guide this. You can then kinda use that as motivation to try building mini versions of these tools, or building some extensions off of these tools to complement them. 

2. **General project ideas repositories** 

    There are general project idea repositories like [Build Your Own X](https://github.com/codecrafters-io/build-your-own-x) or [this list](https://github.com/the-programmers-hangout/programming-resources/blob/master/ideas.md) where you can kinda pick a project that interests you and try building it from scratch to get a feel for what it’s like to build things. 

3. **Hey this is cool** 

    If you browse tech blogs/Twitter/Hackernews/Lobster/etc, you might encounter a project that catches your eye so you might want to try it out or replicate it to learn how it works

4. **Deep dives** 

    You could also be interested in a certain project and take the time to analyze and dissect what the project does. This is similar to the [open-source deep dive series](/post/odd-broadway-1) I had written about.

5. **Following roadmaps**

    Generally these roadmaps are useful starting points and can help you move outwards in terms of figuring out what’s next. A good website for these roadmaps is [roadmap.sh](https://roadmap.sh/)

There is no one way to start building things, but I personally find that the easiest  is to find something that interests you and go deep.
